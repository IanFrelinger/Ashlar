A sibling workflow produced an independent Python model of the open-read rule after this lane's code was written (`scratchpad/model-4.5/REPORT.md`; `frame-model-readscope.py`, the 4.4 no-skip model `ws/frame-model-wd-callback.py` extended with the read frame; `frame-model-pins-readscope.py`, the 4.4 pins model extended likewise; every run's output under `model-4.5/logs/`, from which `gen-report.py` builds the report's tables; the integrator holds these files for the workspace storage branch). The lane checked the modelled rule against the code, not the other way round.

**The modelled rule is the implemented rule.** Its §1 (`correct`, the pinned reading), op by op against `EgressSubject.cs` and `ReadScope.cs` at this head: `BeginRead` pushes a read frame whose `prev` is the flow's head and whose mark is SystemHigh while the read is open (`Frame.ForRead`, `Active.Value = read`); `Resolve` joins every frame's mark from the head down to a detachment, the read frame's included, so a subject frame entered inside the read decides SystemHigh; `Observe` inside the scope raises every subject frame on the chain (`ObserveInto` passes through the read frame); forked work inherits the read frame (`AsyncLocal`); `ReadScope.Dispose` computes the result as 4.4 did (the join of the reports iff `Complete` was called and at least one report was made, else SystemHigh), observes it into the chain the read was begun on, and then disposes the read frame, which the flow leaves only when it is that flow's own undisposed head (the no-skip rule; every other flow stays inside, fail closed); a `Report` before `Dispose` lowers nothing (the model's §9 Q3 reading, which is this PR's "not yet ended"); the read frame's mark is SystemHigh for life, so a flow that could not leave it decides SystemHigh from then on (pinned, not `settled`); and the basis of a decision inside a read is the nearest live subject frame's (§6.4's suggestion, implemented as `Live` skipping read frames). Two details differ in form, not effect: a late `Report` observes into the begun-on chain rather than "the read frame included", and every read frame shares one static `HighWaterMark(SystemHigh)` rather than carrying its own; under the pinned reading that mark can never change, so neither is observable. §5: no exact frame count a 4.4 growth twin pins changes, because the rule adds a frame only when `BeginRead` is called and none of those twins calls it; no twin pin was updated. §6's checklist: both flips are made by name (6.1); production's wiring is in order on one flow (6.3); the basis is the nearest live subject (6.4); a read with no frame keeps 4.4's behaviour and `With_no_frame_a_read_changes_nothing` stands (6.5); §10's unverified runtime fact (an `AsyncLocal` write inside an `async` helper persists across that helper's later awaits) holds, since `An_awaited_read_that_throws_observes_SystemHigh` passes with the read frame.

The report's wording (§8), quoted:

> **Read frames (owner decision 2026-10-06).** `BeginRead` pushes a read frame onto the flow whose mark is SystemHigh while the read is open, so every decision on that flow, and on every task, continuation or thread started inside the scope, is SystemHigh until the scope ends; `Observe` inside the scope still raises every subject frame on the chain. Disposing the scope observes its result into the chain it was begun on, exactly as before (the join of the reports if `Complete` was called and at least one report was made, else SystemHigh), and leaves the read frame by the 4.4 rule: only the flow whose own undisposed head it is goes back to the frame it was begun under; every other flow stays inside it (fail closed). A Python model of the rule over flows with Enter, Dispose (in order, out of order, on another flow, inside an awaited helper, late), Observe, fork, `RunDetached` brackets, BeginRead, Report, Complete and Dispose checked four properties after every op (no write-down; an open read decides SystemHigh; no-skip with read frames present; a mis-disposed read lowers no mark and moves no flow) over 41,755,599 sequences in all (the largest single bound: 20,664,823 sequences at N=7, up to 2 flows, ops A C/U E K O P R Y Z (+X, +T), 1019 s of CPU), and found no violation. With no read ops the model reproduces the 4.4 model's 1,900,357 sequences exactly. The same harness catches four broken variants first: the open scope not counted (master before this PR) in 2 ops (`Enter ; BeginRead`), a Dispose that pops a read frame that is not the head in 3, forked work that does not inherit the read frame in 3, and a Report before Complete that satisfies a read that then throws in 4. No exact frame count a 4.4 growth twin pins changes: the rule adds a frame only when `BeginRead` is called, and none of those twins does.
