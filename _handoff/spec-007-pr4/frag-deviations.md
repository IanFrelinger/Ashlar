**Integrator decisions on the model report's §9 (recorded here, in the `EgressSubject`/`ReadScope` remarks and in row 66; the SPEC-007 decisions-log row carries only the owner's rule as worded):**
1. **Pinned, not settled.** The read's frame's mark is `SystemHigh` for its whole life and never lowers when the read ends. Why: every mark stays monotone as in 4.4 (a mark that goes down at dispose would be a new concept); it is the simplest rule under the unchanged one-line invariant ("every frame on a chain counts at its mark down to a detachment"); both readings pass the model's P1–P4, so the only cost is availability for a flow that could not leave a read frame, which is limit (a) territory already. Consequence, flipped by name: `A_read_observes_into_every_live_frame_of_its_chain_from_whatever_flow_it_ends_on` (the scope disposed inside `Task.Run`; the main flow stays inside the read's frame and now decides `SystemHigh`, `SystemHighData`, where it pinned `LevelTooLow`). `A_completed_read_with_no_report_observes_SystemHigh`'s "inside the open scope is `Public`" assertion flips by name for the owner's rule itself.
