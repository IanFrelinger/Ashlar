# Ashlar product boundary (CEO lock)
**Date:** 2026-09-19 · **Owner:** Marketing/Product 3000  
**Status:** Product lock — Delivery/Dogfood/Arch align; Autonomy/Learn HOLD for GTM

---

## Center

**Ashlar governs behavior, not intelligence.**

It turns AI-generated know-how into **verified, reusable behavior** you can audit, move between systems, and run under constraints.

Everyday: not a chat box · control layer · receipts + bouncer (Joe: plugin/recipe + checked before it runs).  
Precision (builders): contracts · admission gate · trust log / audit trail · portable packages · model abstraction.

**Heart:** Agents may propose. **Ashlar owns authority** — evidence, admission, promotion. If an agent can modify the thing that decides whether its modification is trusted, the architecture has eaten its own safety boundary.

---

## Architecture picture (public)

```
propose → ASHLAR GATE → admitted → portable package → hosts re-check contract → receipt
```

Mental model: **JVM for behavior** — portable verified behaviors, not a chatbot, not a package manager alone.

### Prompt certification (gate vision — architecture yes / GTM when proven)
Same prompt (or prompt pack) across approved models → **same required behavior** under witness/tests → verified prompt packs → swap models safely. Not "same bytes every time." Live vs vision: ship gate/receipts/packages first; prompt-pack GA only with evidence.
