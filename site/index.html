Auditable workflows

Submit a task and you get the output and the record of what ran. Every task is stored under an id, and the trust log carries an entry whose sourceId is that id.

# Submit an audited task POST /api/copilot/task { "task": "Summarize this repository" } # Response includes task record: { "taskId": "task-a7f9...", "success": true, "summary": "1 agent(s) executed" } # Trust log carries the audit entry: GET /api/trust/dashboard # sourceId matches the taskId
Certified

Certification gate

Code that Ashlar—or a model—proposes only becomes trusted after the certification gate: analyzer fence → witness → mutation testing → determinism.

The gate is a required CI check on master (cert-gate) alongside build integrity, shell syntax, and docs verification—and every ADMIT/REJECT it has proven is a row in docs/certification-evidence.md.

Your infrastructure

Runs as a CLI, an HTTP API, containers, or embedded in your own host.

# Run locally ashlar doctor # Or embed in your app dotnet add package Ashlar.Client # Configure HTTP client services.AddAshlarClient( "http://localhost:5000" );

Build on Ashlar

Embed as a NuGet dependency. Integrate via HTTP. Run the CLI. Deploy with Docker. Your choice.

// Add the Ashlar client builder.Services.AddAshlarClient(baseUrl: "http://localhost:5000"); // Submit a task via HTTP API var response = await client.InvokeAsync( HttpMethod.Post, "/api/copilot/task", JsonContent.Create(new { task = "Analyze this dataset" }) );

Local-first operation

Local model routing (Ollama) is the default route. Cloud providers are opt-in targets. Air-gapped and local-only deployments are first-class.
